# Скелет инструмента-плагина (`_template`)

Эта папка **не подключается** к агенту: имена папок, начинающиеся с `_`,
`core/tool_discovery.py` игнорирует. Это рабочий образец: скопируй папку под
рабочим именем — и инструмент появится у агента сам.

```bash
cp -r tools/_template tools/my_tool     # появился
rm -rf tools/my_tool                    # исчез (без правок в core/)
```

Ничего в `core/` править не нужно: реестр, схемы, каталог и payload собираются
сканированием папок.

## Состав папки (контракт)

| Файл | Обязателен | Назначение |
|------|-----------|------------|
| [`tool.json`](./tool.json) | да | манифест подключения — единственный источник правды |
| `__init__.py` | да | реализация; `entry`-функция принимает аргументы модели |
| `README.md` | да | описание от разработчика (этот файл — его образец); без него инструмент не подключится |

## Манифест [`tool.json`](./tool.json)

```json
{
  "name": "my_tool",
  "entry": "execute",
  "aliases": [],
  "provides": ["session_path"],
  "danger": ["session_write"],
  "always_on": false,
  "description": "Короткое описание для модели",
  "schema": { "type": "function", "function": { "...": "..." } }
}
```

| Поле | По умолчанию | Что делает |
|------|--------------|------------|
| `name` | имя папки | id инструмента в каталоге, payload и вызовах |
| `entry` | `execute` | путь к функции внутри пакета (точечный: `execute`, `main.run` — подмодуль папки тоже поддерживается) |
| `aliases` | `[]` | дополнительные имена для вызова (своей схемы у алиаса нет) |
| `provides` | `[]` | что платформа передаёт в вызов: `session_path`, `progress` (живой прогресс), `dangerous_mode` |
| `danger` | `[]` | классы опасности: `shell` (опасные action целиком), `session_write` (мутации файлов внутри папки сессии), `session_output` (запись вывода в файл внутри сессии) — вне сессии требуют dangerous mode |
| `always_on` | `false` | всегда в payload (только для ядра харнесса: `tools`, `sign_step`, `session_memory`) |
| `description` | докстрока | короткое описание для каталога/автосхемы |
| `schema` | — | полная OpenAI-схема; **если не указана — генерируется из сигнатуры** (типы из аннотаций, `required` — параметры без дефолта) |

Объявленное в `provides`, но отсутствующее в сигнатуре, молча не передаётся —
контракт декларативен, сигнатура решает. Объявленный `danger` работает и для
сторонних плагинов: гейт dangerous mode смотрит на класс опасности, а не на имя
инструмента.

Нарушения контракта (битый JSON, нет `README.md`, схема не совпадает с `name`,
занятое имя/алиас) — инструмент не подключается и виден агенту как сломанный
с причиной.

## Тезисы: как писать «умный» инструмент

Инструмент — это не обёртка над вызовом, а **решение задачи для модели**.

1. **Описание — для модели, не для человека.** В `description`/докстроке: что
   делает, *когда* звать, что вернёт, что делать дальше. Каталог показывает
   первое предложение — оно должно быть самодостаточным.
2. **Один инструмент — одна задача.** Вместо россыпи мелких вызовов делай
   `action`-и (короткий `enum`), но не превращай инструмент в DSL.
3. **Возвращай отчёт, а не дамп.** Строка с фактами: `file.py:12`, размер,
   время, статус, — и явный «следующий шаг». Никаких простыней сырых данных:
   лишнее кладётся в артефакт, а в ответ — путь и краткая сводка.
4. **Ошибка — тоже результат.** Возвращай `Error: <причина>` и что попробовать
   вместо; исключения наружу не пропускай (они логируются как сбой вызова).
5. **Безопасные дефолты.** Мутации — только внутри папки сессии; сеть — с
   таймаутом и лимитом байт; секреты не логируй и не печатай.
6. **Ленивость.** На импорте — только константы и объявления: тяжёлые
   зависимости (httpx, Pillow, …) импортируй внутри функций. Модуль
   импортируется при подключении/первом вызове.
7. **Идемпотентность и симметрия.** `get`/`set`, `enable`/`disable`,
   `read`/`write` — парные действия с предсказуемым поведением; повторный
   вызов не должен ломать состояние.
8. **Действие `help`.** Дешёвая справка (`action=help`) экономит токены модели
   и снимает догадки о формате.
9. **Самодостаточность.** Плагин зависит только от stdlib и `requirements.txt`;
   общие помощники бери из `tools/<helper>.py`, но не дёргай чужие `entry`
   напрямую — только через их публичные функции.
10. **Тест как часть контракта.** Проверь инструмент на temp-сессии и прогони
    контракт плагинов целиком (см. ниже).
