# План: измерение и улучшение харнеса ботинка (по всем категориям)

## Идея

Качество агента = f(модель, харнес) (PawBench). Модель фиксируем — получаем чистую меру
харнеса: **каждый узел харнеса либо двигает счётчик, либо занимает место**. Дальше цикл:
мерим → чиним худший слайс → таргет-репрогон только его. Память (FORGOTTEN_INDEX) —
один слайс из многих, не центр мироздания.

## Методология и источники

- **PawBench** (github.com/agentscope-ai/PawBench, 06.2026): матрица Model × Harness,
  режимы «fix model — vary harness» и «vary model — fix harness», пятиосевая разметка
  задач (scenario/capability/complexity/modality/environment), reuse-and-tag из чужих
  бенчмарков, срезы-диагностика. Разброс харнесов при фиксированной модели 10–11.5 балла.
- **Harness-Bench** (arXiv 2605.27922): конфигурации харнеса при общих бюджетах/протоколе.
- **Terminal-Bench / SWE-bench-2026**: свинг скаффолда до 22 баллов при модели ±1 —
  обоснование, почему мерить надо харнес, а не модель.
- Внутреннее: `tests/selfcheck/` (15 задач L1–L4, SCORECARD pass@1/Pass^k, таксономия
  ошибок) — готовое ядро набора; [[context_memory_research]] — слайс памяти.

## Набор задач (reuse & tag)

Слайсы по категориям инструментов ботинка, каждая задача — MD-карточка как в selfcheck
(подготовка → задание → критерии → формат отчёта) + теги PawBench-осей:

| слайс | источник задач | что меряет |
|---|---|---|
| edit/grep/read | selfcheck 01–12 (есть) | edit-кит, file_system |
| shell/dangerous | selfcheck 13–15 + новые PTY-задания | shell_exec, подтверждения, inline-панель |
| web/загрузки | новые: фикстуры локального http-сервера | `web`, aria2c, прокси, навигатор |
| память/история | LongMemEval-формат на sample-сессиях | FORGOTTEN_INDEX, session_memory |
| skills/experience | новые: навык-инструкция +执行 | discovery, мемо каталогов |
| мультимодальность | image/vision на фикстурах | image, chafa, truecolor |
| safety | unanswerable/деструктивные задания | dangerous mode, отказ от выдумки |

## Эксперимент 1: базовая линия

Модели заморожены: `gemma4:e2b`, `qwen3.5:9b` (+ одна сильная для калибровки потолка).
Текущий HEAD — базовая линия. Прогон всего набора, Pass^3, отчёт SCORECARD-формата:
полная карта «где харнес слаб».

## Эксперимент 2: абляции узлов (главный)

При фиксированной модели включаем/выключаем по одному узлу, сравниваем только свой слайс
+ общий регресс:

- ступенчатое раскрытие инструментов ON/OFF;
- FORGOTTEN_INDEX vs биг-бенг vs наивный тримм;
- pressure-инжект ON/OFF; sign_step ON/OFF;
- директивы tool_policy ON/OFF;
- шимы подсказок (навигатор страниц, каркас-советник code_editor) ON/OFF.

Вопрос каждого узла: **двигает ли он счётчик вообще**. Узел, не двигающий ни один слайс, —
кандидат на удаление (дешевле контекст и сложность).

## Метрики

Pass^k (k=3), доля выдумок (unanswerable), токены контекста на задачу, латентность,
число лишних tool-вызовов, таксономия ошибок по SCORECARD. Судья — фиксированный
промпт + ручная выборка 20%.

## Порядок

1. теги и разметка существующих 15 задач (полдня);
2. новые задачи слайсов web/safety/skills/multimodal (день, переиспользуем фикстуры тестов);
3. базовая линия на e2b (прогон ночью);
4. абляции по одному узлу за прогон;
5. отчёт: карта слайсов + список узлов без вклада + план правок худших слайсов.

Внешний контур: завести ботинок в PawBench как харнес-адаптер — внешняя сопоставимость
против QwenPaw/OpenClaw/Hermes.
