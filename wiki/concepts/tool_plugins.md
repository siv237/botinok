# Плагинные инструменты (папка = инструмент)

Механизм подключения инструментов Ботинока: инструмент — это **папка**, а
манифест в ней — контракт. Реестр, схемы, каталог и payload модели собираются
сканированием (`core/tool_discovery.py`), рукописных таблиц в ядре нет.

## Контракт папки

```
tools/<folder>/
├── tool.json     # манифест подключения (обязателен)
├── __init__.py   # реализация: entry-функция (обязателен)
└── README.md     # описание от разработчика (обязателен)
```

Образец — `tools/_template/` (не подключается: папки с `_` игнорируются).
Скелет содержит манифест-пример и тезисы «умных инструментов».

## Манифест `tool.json`

| Поле | По умолчанию | Значение |
|------|--------------|----------|
| `name` | имя папки | id инструмента (каталог, payload, вызовы) |
| `entry` | `execute` | точечный путь к функции в пакете (`main.run` — подмодуль папки тоже импортируется) |
| `aliases` | `[]` | дополнительные имена вызова (схемы у алиаса нет) |
| `provides` | `[]` | `session_path`, `progress` (progress_callback), `dangerous_mode` |
| `danger` | `[]` | классы опасности: `shell`, `session_write`, `session_output` — гейт dangerous mode берётся из манифеста, а не из имени инструмента |
| `always_on` | `false` | всегда в payload (ядро харнесса: `tools`, `sign_step`, `session_memory`) |
| `description` | докстрока | короткое описание для каталога/автосхемы |
| `schema` | — | полная OpenAI-схема; если нет — генерируется из сигнатуры (типы из аннотаций, `required` = параметры без дефолта) |

Объявленное в `provides`, но отсутствующее в сигнатуре, не передаётся:
контракт декларативен, сигнатура решает (`_accepted_provides`). Политика
«внутри сессии / dangerous mode» (`allowed_in_session`, `requires_dangerous`)
работает по `danger` из манифеста; таблица встроенных имён осталась только как
страховка, если сканирование недоступно.

## Жизненный цикл

- **Подключение**: `discover()` сканирует папку, кэширует результат по отпечатку
  файлов плагинов (mtime_ns/размер манифеста, README и всех `.py` папки —
  mtime самой папки не используется, иначе создание `__pycache__` при первом
  импорте выглядело бы правкой плагина). Импорт реализации ленив: если схема в
  манифесте есть, модуль при сканировании не импортируется.
- **На лету**: `ToolManager._refresh_if_stale()` дёшево сверяет отпечаток перед
  сборкой payload и каждым вызовом; `rediscover()` пересобирает реестр и
  сбрасывает закэшированные вызовы/модули (включая подмодули и `.pyc`) только для
  изменившихся плагинов — состояние остальных инструментов сохраняется. Положили
  папку — инструмент появился, удалили — исчез, поправили код или манифест —
  подхватилось, без перезапуска процесса.
- **Сбой скана** (папка отсутствует/недоступна, например опечатка в
  `BOTINOK_TOOLS_DIR`) — не «ноль инструментов молча»: в `broken_tools` попадает
  `ToolsDirError`, ядро (`tools`/`sign_step`/`session_memory`) остаётся доступным,
  а работа из сторонней папки сопровождается предупреждением в stderr (код
  плагинов исполняется с правами пользователя).
- **Удаление**: удалённый инструмент отсутствует в реестре, `get_tool_definitions()`
  (payload), каталоге (`TOOLS_CATALOG`), `tools(action=enable)` → «неизвестный
  инструмент», `call_tool` → `Error: unknown tool`; старое имя в
  `enabled_tools.json` сессии фильтруется (`enabled_tools()`). «Сломанные
  инструменты» не упоминаются — харнесс не предлагает чинить удалённое.
- **Нарушения контракта** (битый JSON, нет README, `schema.function.name` ≠ имя,
  занятое имя/алиас, неизвестный `provides`) — папка не подключается, попадает
  в `Discovery.invalid` и видна агенту как сломанный плагин с причиной
  (`PluginContractError`). Падающий импорт/`entry` — `broken_tools`.

## Импорт и идентичность модулей

- Инструменты установки грузятся как `tools.<folder>` (единый объект модуля для
  всех потребителей, включая legacy-импорты `from tools import web`).
- Сторонняя папка (`BOTINOK_TOOLS_DIR`, тесты) грузится по пути файла под
  синтетическим пакетом — реальный `tools` не подменяется.

## Откуда берётся «всегда включённое» и известные имена

`tools/tools_catalog/` читает манифесты через `tool_discovery.always_on_names()`
и `known_names()`: каталог, `enable/disable` и фильтр payload следуют за папками,
а не за списком в коде.
