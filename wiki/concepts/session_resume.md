# Возобновление сессии и точное восстановление контекста

Возврат в старую сессию должен быть **неотличим от продолжения**: модель получает состояние, а не «начинает заново». Ключевой принцип — различать **точный результат** и **наметку**.

## Источники и достоверность
- **EXACT** — канонический снапшот `messages.json` (точный входной массив `messages`, медиа вынесено в `artifacts`). Пишется в конце каждого хода. Читается `SessionManager.restore_session()` → `tools/session_memory` action `restore`.
- **DERIVED** — реконструкция из `context.json` (роли, `tool_call_id`, tool-результаты) + `tools.log`. Для старых сессий: пары `tool_call ↔ результат` восстанавливаются по порядку/имени, недостающие добираются из `tools.log`.
- **HINT** — поиск/стемминг/сводки; требует перепроверки.

Снапшот может быть **старше** `context.json` (прерванный ход не успевает записаться) — тогда `restore` помечает `stale`, а хвост смотрят через `get_turn`/`turns`.

## Промпт восстановления
`prompts/resume_session.txt` (глобальный, старые сессии берут через fallback) объясняет агенту:
- сессия восстанавливается, статус (прервана на середине хода / завершена), сколько прошло времени;
- кратко: исходная задача, последний запрос, последнее состояние, размер истории;
- **как получить подробности**: `session_memory action=restore` (EXACT), `resume_brief`, `get_turn`, `search`;
- что делать: не начинать заново, продолжить; если неясно — сказать пользователю и спросить «продолжать? (да/нет)».

На восстановлении инструкции про обязательную проверку `skills`/`experience` **не отправляются вовсе** (`SessionManager.strip_skills_mandate` вырезает их из `tool_policy` и `tool_reminder`); отдельного «отменяющего» промпта нет.

## Устойчивость к обрывам API
`core/textual_integration.py`, `_stream_turn`:
- при обрыве потока (`stream_error`) — автоповтор запроса (до `max_http_retries`); счётчик сбрасывается после успешного стрима;
- при исчерпании попыток — частичный ответ сохраняется как `assistant` (или system-пометка), чтобы не оставался «висящий» `user`;
- сбой соединения / HTTP-ошибка — `_persist_connection_failure` пишет user + system-пометку.

Без этого обрыв выглядел как «сессия перезапущена».
