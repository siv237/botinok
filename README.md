# Проект «Ботинок» — Консольный Агентный ИИ

Агентный ИИ с поддержкой **Ollama** и любых **OpenAI-совместимых API** (OpenAI, llama-server, vLLM). Экстремальный фокус на производительность, прозрачность работы LLM и детальный аудит сессий. Полностью консольный интерфейс с богатым форматированием.

## Концепция
Цель проекта — создание автономного консольного агента, способного эффективно решать задачи программирования, поиска информации и системного администрирования в системах с малым объемом VRAM за счет глубокой оптимизации рабочих процессов.

## Основные возможности
- **Продвинутый консольный UI (Textual)**: Интерактивный интерфейс с цветовым форматированием, живой статистикой VRAM, TTFT (Time To First Token), TPS (Tokens Per Second), визуализацией процесса размышлений (thinking) и встроенным терминалом (PTY-сессии `shell_exec` со сворачиванием окон).
- **Умное управление контекстом**:
    - Скользящее окно памяти: старые ходы плавно вытесняются вместо сброса истории разом; агент держит каталог «забытого» и поднимает любой фрагмент по требованию (`session_memory`).
    - Генерация **SESSION_PROTOCOL** при переполнении: модель сама суммаризирует важные факты и намечает следующие шаги.
- **Система инструментов (Function Calling)**: Богатый набор инструментов для взаимодействия с миром.
- **Безопасность (Dangerous Mode)**: Потенциально опасные действия (правка кода вне папки сессии, выполнение shell) по умолчанию отключены и включаются аргументом `--dangerous` или подтверждением пользователя по ходу работы.
- **Внешние системные промпты**: Все системные сообщения вынесены в `prompts/`. Каждая сессия получает свою копию, которую можно редактировать для тонкой настройки поведения агента.
- **Полная прослеживаемость**: Каждая сессия сохраняет все мысли, вызовы инструментов и артефакты в структурированном виде.

## 🚀 Быстрый старт — три шага

**Шаг 1. Скачай и установи** (одна команда, всё нужное поставится само):
```bash
curl -sSL https://raw.githubusercontent.com/siv237/botinok/main/install.sh | sudo bash
```

**Шаг 2. Запусти мастер настройки** — он спросит, где твой LLM-сервер (Ollama или любой OpenAI-совместимый API), покажет список моделей и сохранит настройки:
```bash
botinok --wizard
```

**Шаг 3. Запусти агента:**
```bash
botinok
```

Готово — откроется интерфейс, можно задавать вопросы. Опытным: мастер не обязателен, ботинок запускается и одной строкой без всяких настроек (`botinok --backend openai --base-url ... --api-key ... -m модель "задача"`), а одиночные запросы и режим для скриптов описаны в [использовании](#использование).

## Архитектура инструментов

Все инструменты динамически загружаются через `core/tool_manager.py`.

### 🌐 Сеть и поиск
- **web** — Единый добыватель данных: `action=search/open/extract/json/download/downloads/help`.
  Загрузки через **aria2c** (докачка, большие файлы/ISO, торренты `magnet:`/`.torrent`),
  проверка типа/HTML-заглушек/`sha256`, глобальная память загрузок `~/.botinok/downloads/history.json`.
- **web_search / open_url / web_extract / curl** — legacy-алиасы `web` (работают, но для новых задач используй `web`)

### 🛠 Системные инструменты
- **file_system** — Навигация, поиск (grep, find), чтение и инспекция файлов. Продвинутый `find` с фильтрами по размеру, времени, типу.
- **shell_exec** — Выполнение bash-команд (требует `--dangerous`)
- **journal** — Анализ системных логов `journalctl`

### 💻 Разработка и Навыки (Skills)
- **code_editor** — Полноценное редактирование файлов (чтение, запись, замена фрагментов)
- **github** — Работа с репозиториями (clone, log, status, diff)
- **skills** — Мощная система расширения функционала
    - `Personal`: `~/.botinok/skills/` — приватные навыки пользователя
    - `Project`: `./skills/` — общие навыки проекта

### 🧠 Опыт и память
- **experience** — Локальная база данных «позитивного» и «негативного» опыта. Агент учится на своих ошибках
- **session_memory** — Структурированный доступ к истории прошлых сессий: поиск по содержимому, чтение сохранённых файлов, артефактов и мыслей

### 🖼️ Мультимодальность
- **image** — Показ изображений прямо в чате (в том числе по ssh, в настоящих цветах)
- **audio** — Анализ аудио (omni-модели): файл или URL, автоконвертация в WAV 16кГц моно
- **vision** — Анализ изображений мультимодальной моделью
  - Автоматическая проверка формата и разрешения
  - Поддержка: JPEG, PNG, GIF, BMP, WebP (и любые другие через конвертацию)
  - Автоконвертация в RGB JPEG при необходимости (прозрачность, неподдерживаемые форматы)
  - Авторесайз до лимитов модели (4096×4096 для Qwen3.5, уменьшает но не увеличивает)
  - Источники: локальный файл или URL

**Примеры использования:**
```
Анализ фото: vision(image_path="/path/to/photo.jpg", prompt="Что на изображении?")
Скриншот сайта: vision(url="https://example.com/screenshot.png")
```

## Управление сессиями и контекстом

Каждый интерактивный запуск создает директорию `sessions/<timestamp>_<name>/`. Одиночный запрос (`botinok "..."`, `--stealth`, pipe) создает **временную** сессию, которая удаляется после ответа.

### Структура сессии:
- `context.json`: Полная история диалога и состояние памяти.
- `thinking.md`: Лог всех размышлений модели (thinking block).
- `response.md`: Финальные ответы без служебной информации.
- `tools.log`: Детальный технический лог вызовов (время, аргументы, размер ответа).
- `session_raw.log`, `performance.log`: Сырой лог хода и метрики (TTFT/TPS/контекст).
- `steps/`: Шаги многошаговых задач.
- `artifacts/`: Сюда сохраняются дампы больших ответов инструментов (HTML, JSON, ошибки), чтобы не раздувать контекст LLM.
- `project/`: Песочница для опасных действий внутри сессии (разрешены без подтверждений).
- `prompts/`: Копия системных промптов, специфичная для сессии.

## Системные промпты

Все системные сообщения вынесены в отдельные текстовые файлы в папке `prompts/`. При создании сессии они копируются в `session/prompts/`, что позволяет:
- Настраивать поведение агента для конкретной сессии
- Возвращаться к промптам сессии при продолжении работы
- Использовать глобальные промпты для новых сессий

Файлы промптов:
- `identity.txt` — кто такой ботинок, общий тон поведения
- `system_time.txt` — информация о текущем времени
- `session_location.txt` — папка запуска, пути к сессии и project/
- `session_files.txt` — карта файлов сессии
- `tool_policy.txt` — политика использования инструментов
- `tool_reminder.txt` — напоминание перед каждым ходом
- `dangerous_mode.txt` — статус dangerous mode
- `broken_tools.txt` — информация о неработающих инструментах
- `resume_context.txt`, `resume_session.txt` — контекст при продолжении сессии
- `chat_only.txt` — режим без инструментов
- `context_trimmed.txt` — уведомление при обрезке контекста
- `context_overflow_protocol.txt`, `context_overflow_summary.txt`, `context_overflow_user.txt` — протокол и суммаризация при переполнении контекста
- `auto_continue.txt`, `auto_continue_final.txt` — автопродолжение оборванного ответа
- `proofreader.txt` — инструкции для корректора

**Важно:** Если файл отсутствует в `session/prompts/`, используется версия из глобальной `prompts/` (или `/opt/botinok/prompts/` для установленной версии).

## Безопасность (Dangerous Mode)

По умолчанию опасные действия (shell, запись вне папки сессии) запрещены. Варианты включения:

```bash
botinok --dangerous        # разрешить сразу, без вопросов
botinok                    # в TUI каждое опасное действие подтверждается отдельно (y/n + причина)
botinok "запрос"           # в одиночном режиме агент спросит разрешение в консоли, когда действие понадобится
```

В pipe/stealth-режиме спросить некого — без `--dangerous` опасные действия не выполняются.
Опасные действия **внутри папки сессии** (песочница `session/project/`) разрешены всегда и подтверждений не требуют.

## Технический стек и бэкенды

Ботинок работает с двумя типами бэкендов (выбирается в мастере, конфиге или флагом `--backend`):
- **Ollama** (по умолчанию, `localhost:11434`) — локальный или сетевой инстанс [Ollama](https://ollama.com), включая его облачные модели (например, `minimax-m2.7:cloud`) — для бота это обычная модель Ollama, отдельная настройка не нужна.
- **OpenAI-совместимый API** (`--backend openai`) — OpenAI, llama-server, vLLM и любые другие API формата `{base}/v1/chat/completions` с ключом `--api-key`.

**ВАЖНО:** Для полноценной работы инструментов (tools) нужна модель с поддержкой **Function Calling** (например, `qwen2.5`+, `llama3.1`+, `mistral-nemo`).

- **Контекст:** по умолчанию 8192 токена (`-c` для переопределения).

## Использование

### 1. Интерактивный режим (стандартный)
Полноэкранный Textual-интерфейс: выбор/продолжение сессий, стриминг с markdown, спойлеры размышлений, живая статистика (TTFT/TPS/VRAM/контекст), встроенный терминал `shell_exec`, темы (ночь/день/вечер):
```bash
botinok
```

### 2. Одиночный запрос
Без интерфейса и выбора сессии: агент выполнит задачу и напечатает ответ. Сессия временная. Рабочая папка — та, из которой запущен `botinok` (в ней работают `file_system`, `shell_exec` и относительные пути вроде `.`):
```bash
cd ~/projects/myapp
botinok "изучи этот проект и расскажи, что он делает"
botinok "Проанализируй логи в /var/log/syslog и найди ошибки сети"
botinok --once "Сколько свободно места на /"   # ответил — вышел
```

### 3. Режим для скриптов (Stealth)
Выводит ровно финальный ответ модели и больше ничего — ни служебных строк, ни пустых строк, stdout чистый для конвейеров и `$()`. Сессия временная, удаляется после ответа. Спросить некого, поэтому опасные действия без `--dangerous` не выполняются:
```bash
botinok --stealth "Сколько оперативной памяти свободно?"
память=$(botinok --stealth "Сколько оперативной памяти свободно?")
```

### 4. Работа в конвейере (Pipe mode)
Бот автоматически определяет наличие данных в `stdin`. Это позволяет использовать его для обработки вывода других команд:
```bash
# Передача логов для анализа
tail -n 100 /var/log/syslog | botinok "Найди критические ошибки"

# Передача содержимого файла
cat script.py | botinok "Объясни, что делает этот код"

# Быстрый вопрос через echo
echo "Как сварить кофе?" | botinok
```
В Pipe-режиме (если это не интерактивный терминал) бот работает как одиночный запрос без интерактива: выводит только ответ, опасные действия без подтверждения не выполняет. Сессия временная и удаляется после ответа.

### 5. Выбор модели и контекста
```bash
botinok -m qwen3.5:9b -c 16384 --dangerous
```
Параметры:
- `-m MODEL`: Имя модели (по умолчанию из конфига).
- `-c CTX`: Размер контекста (например, `16384` или `32768`).
- `--dangerous`: Активация опасных инструментов (`code_editor`, `shell_exec`) без вопросов; работает и в интерактивном, и в одиночном режиме.
- `--stealth`: Только ответ, без прогресса и вопросов (для скриптов).
- `--once`: Один запрос без вопроса о продолжении (ответил — вышел).
- `--wizard`: Запуск интерактивного мастера настройки.
- `--update`: Проверить и установить обновления из git.
- `--ensure-deps`: Проверить и установить системные зависимости (chafa, ffmpeg, aria2 и др.).
- `--view-history PATH`: Открыть историю сессии в просмотрщике с прокруткой.
- `--debug`: Включить отладочный вывод.
- `--version`: Показать версию и дату коммита.
- `--proofread`: Режим корректора (цикл: Исполнитель → Корректор).
- `--backend ollama|openai`: Бэкенд без конфига и мастера (env `BOTINOK_BACKEND`).
- `--base-url URL`: Адрес сервера без `/v1`, напр. `http://localhost:11434` или `https://api.openai.com` (env `BOTINOK_BASE_URL`).
- `--api-key KEY`: Ключ для openai-бэкенда, без ввода в мастере (env `BOTINOK_API_KEY`).

### 6. Запуск без конфига и мастера (одной строкой)
Свежеустановленный ботинок на любом компе сразу работает — сервер, ключ и модель задаются флагами прямо в команде:
```bash
botinok --backend openai --base-url https://api.openai.com --api-key sk-... -m gpt-4o --dangerous --once "собери список самых больших файлов в текущей папке"
```
Через переменные окружения (ключ не светится в истории команд; удобно прописать в `~/.bashrc`):
```bash
export BOTINOK_BACKEND=openai BOTINOK_BASE_URL=https://api.openai.com BOTINOK_API_KEY=sk-...
botinok -m gpt-4o "изучи текущую папку"
```
Флаги/env переопределяют `config.cfg`, но не пишут в него. Без них берутся значения из конфига (а при отсутствии конфига — Ollama на `localhost:11434`).

### 7. Обновление
Проверить и установить обновления из git-репозитория:
```bash
botinok --update
```
Если доступна новая версия, будет показано сравнение версий и запрошено подтверждение перед установкой.

## Настройка
Мастер настроит бэкенд (Ollama или OpenAI-совместимый API), URL, модели и контекст:
```bash
botinok --wizard
```
Приоритет конфигурации: персональный `~/.config/botinok/config.cfg` → локальный `config.cfg` в папке установки → системный (путь можно задать переменной `BOTINOK_CONFIG`). Флаги `--backend/--base-url/--api-key` переопределяют конфиг на время запуска, не изменяя его.

## Разработка новых навыков (Skills)
Новые навыки добавляются в папку `skills/`. Каждый навык должен содержать файл `SKILL.md` с описанием возможностей и реализацию на Python, которая подключается через `tools/skills.py`.
