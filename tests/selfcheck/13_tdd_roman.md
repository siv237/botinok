# 13. TDD: написать модуль и прогнать тест

- Уровень: **L4** (нужен dangerous mode)
- Время: ~12 мин
- Инструменты: `code_editor` (write, read), `shell_exec` (run)
- Dangerous mode: **да** (запуск `python`)

## Подготовка

Создай файл `project/SPEC_roman.md`:

```
# Римские числа

to_roman(n: int) -> str
  - 1 <= n <= 3999
  - арабское число -> строка римскими цифрами (классические правила)
  - вне диапазона — ValueError

from_roman(s: str) -> int
  - корректная строка римскими цифрами -> число
  - невалидный ввод — ValueError
```

## Задание

1. Создай `project/roman.py` с функциями `to_roman`, `from_roman`.
2. Создай `project/test_roman.py` с самопроверкой (без pytest обязательно —
   достаточно `assert`-ов и запуска как скрипта), покрывающей:
   `1→I`, `4→IV`, `9→IX`, `40→XL`, `1987→MCMLXXXVII`, `3999→MMMCMXCIX`,
   обратное преобразование и два `ValueError`.
3. Запусти тест через `shell_exec`, добейся успешного прохождения.
4. Если тест падает — читай вывод, правь, перезапускай, пока не станет зелёным.

## Критерии приёмки (проверь сам)

- [ ] `roman.py` и `test_roman.py` созданы.
- [ ] `shell_exec` вернул успешный код (0) и сообщение об успехе теста.
- [ ] Тест реально запускался (в отчёте — команда и хвост вывода).
- [ ] Тест покрывает все перечисленные случаи.
- [ ] Повторный запуск тоже зелёный (стабильность).
