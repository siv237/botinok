# 10. Реализация модуля по спецификации

- Уровень: **L3**
- Время: ~8 мин
- Инструменты: `code_editor` (write, read), `file_system` (list/grep)
- Dangerous mode: не нужен

## Подготовка

Создай файл `project/SPEC_validators.md`:

```
# Спецификация validators.py

is_email(s) -> bool
  - True, если строка вида name@domain.tld
  - ровно один символ '@', непустые части, в домене есть '.', без пробелов
  - иначе False

is_phone(s) -> bool
  - True, если строка состоит только из цифр, '+', '-', '(', ')', ' '
  - и в ней не менее 10 цифр
  - иначе False

normalize_phone(s) -> str
  - оставить только цифры; если строка начинается с '+', сохранить '+' в начале
  - пример: "+7 (999) 123-45-67" -> "+79991234567"
```

## Задание

1. Создай `project/validators.py`, реализующий спецификацию (обычные функции,
   без внешних зависимостей).
2. Создай `project/validators_examples.md` с таблицей «вход → ожидаемый результат»
   минимум на 6 примеров, включая пограничные.
3. Проверь статически: имена функций присутствуют, примеры согласуются с логикой.

## Критерии приёмки (проверь сам)

- [ ] `project/validators.py` содержит `is_email`, `is_phone`, `normalize_phone`.
- [ ] Логика соответствует спецификации (для `is_email` — один `@`, точка в домене;
      для `is_phone` — не менее 10 цифр; `normalize_phone` сохраняет ведущий `+`).
- [ ] `validators_examples.md` содержит ≥6 строк, включая:
      `""`, `"a@b"`, `"a@b.c"`, `"+7 (999) 123-45-67"`.
- [ ] `grep` подтверждает наличие всех трёх `def`.
- [ ] Ничего вне `project/` не изменено.
