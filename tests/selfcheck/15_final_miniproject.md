# 15. Финальный экзамен: мини-проект end-to-end

- Уровень: **L4** (нужен dangerous mode)
- Время: ~20–30 мин
- Инструменты: `code_editor`, `file_system`, `shell_exec`, `session_memory`
- Dangerous mode: **да**

## Задание

С нуля собери в `project/` мини-утилиту учёта задач (todo CLI) и доведи до
зелёного теста.

Требования:

1. `project/tasks.py` — модель данных и логика:
   - `add_task(state, title)` → добавляет задачу с уникальным `id`, статус `open`;
   - `complete_task(state, task_id)` → помечает `done`, ошибка при неизвестном id;
   - `list_tasks(state, status=None)` → список, фильтр по `open`/`done`;
   - `stats(state)` → `{"total": N, "open": N, "done": N}`.
   - Состояние — обычный `dict`, сериализуемый в JSON.
2. `project/storage.py` — `save(state, path)` и `load(path)` через `json`
   (сохранять атомарно, как это делает редактор: временный файл + замена).
3. `project/cli.py` — точка входа с аргументами `add/complete/list/stats`,
   работающая с файлом `project/tasks.json`.
4. `project/test_tasks.py` — самопроверка логики (assert-ы, запуск как скрипт),
   включая: добавление, завершение, фильтр, статистику, ошибку на неизвестный id.
5. `project/README.md` — краткое описание: назначение, примеры команд, как запускать тесты.

## Порядок работы (обязателен)

1. Сначала прочитай это задание и **составь план** из шагов.
2. Создай файлы через `code_editor`.
3. Запусти тест через `shell_exec`; чини до зелёного.
4. Прогони CLI: `add`, `list`, `complete`, `stats` — покажи вывод.
5. Проверь `tasks.json` чтением и `grep`.
6. В конце — отчёт с чек-листом.
