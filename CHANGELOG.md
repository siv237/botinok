## [Unreleased]

### Исправлено отображение изображений в чате (chafa 1.8)
- Причина: рендер передавал chafa флаг `--animate`, которого **нет в chafa 1.8.0** (Ubuntu 22.04) → команда падала (rc=1), `render_image_band` возвращал `None`, `ImageBlock` оставался пустым placeholder'ом даже при установленном chafa
- Флаги chafa теперь формируются по возможностям установленной версии (`chafa_caps()` из `chafa --help`, кэш): `--animate off` добавляется только если поддерживается
- Тест `tests/test_chafa_args.py` (проверяет аргументы для старой/новой версии и реальный полосовой рендер); `test_image_scaling`, `test_image_in_chat`, `test_lazy_images` снова зелёные

### Обновление и системные компоненты (chafa/ffmpeg)
- Исправлено: `botinok --update` на актуальной версии делал ранний `return` и не доустанавливал системные компоненты — из-за этого отсутствие `chafa` не лечилось и картинки в чате не рисовались (`render_image_band` без chafa возвращает `None`)
- `_ensure_system_deps()` ставит **весь** набор (`curl`, `lynx`, `jq`, `aria2c`, `file`, `git`, `chafa`, `ffmpeg`) и вызывается из `--update` **всегда**, независимо от наличия нового коммита; `chafa`/`ffmpeg` добавлены в `_SYSTEM_TOOLS`, поэтому предупреждение о зависимостях их показывает
- Новый флаг `botinok --ensure-deps`; `botinok -U`/`--update-packages` теперь после pip ставит и системные компоненты; `update.sh` — единая команда обновления под root (`git pull` с `safe.directory` → pip → `--ensure-deps`)
- `install.sh` доустанавливает `ffmpeg` (транскод аудио); тест `tests/test_system_deps.py`

### Веб-кит: помощник-навигатор, поиск картинок, прокси, движки загрузки
- **Помощник-навигатор**: после любого fetch — `📦 На странице` (images/links/headings/tables/meta) и готовые вызовы под содержимое, включая `image(source=…)`; для JS-страниц без картинок — подсказка `action=images`
- **`web action=images`** (generic, без сервисов в коде): собирает прямые картинки со страницы/выдачи, проверяет каждую (код + content-type + magic), ранжирует по размеру; готовые `image(source=…)` в ответе
- **`core/net_config.py`** — единый прокси для веб-кита: прощающий ввод + нормализация, приоритет call>session>global>env (пустые env игнорируются), раздача в httpx/requests/aria2c(`--all-proxy`)/env; `web action=proxy show/set/clear/test` — `test` проверяет реальный запрос по обоим движкам и подтверждает; наследуют `web`, `image`, `vision`, `audio`; без хардкодов адресов и навязывания
- **Движки загрузки**: aria2c — большие файлы/докачка/торренты, HTTP-клиент — методы/тело/JSON/API; при сбое aria2c авто-повтор через httpx, ошибка aria2c читаема; `download` картинки предлагает показать через `image`
- **`image`**: классификация ошибок (403/404/429/5xx/timeout/сеть) и память неудач хоста на TTL (защита от зацикливания); загрузка через прокси
- **`audio`**: в `url` принимается локальный путь/`file://` (не «missing protocol»); загрузка через прокси
- Схемы `web` (`images`/`proxy` + `proxy/no_proxy/scope/command`) и промпты; тесты `test_net_config.py`, `test_audio_local.py`, дополнены `test_web_kit.py`, `test_image_catalog.py`

### Исправлено залипание UI при движении мыши (maximize)
- Textual включает any-event mouse (`?1003h`), и на каждое движение мыши терминал слал `MouseMove`; Textual на каждое событие рендерил контент виджета под курсором — на большой chafa-картинке это лавина событий и «зависание» при развороте окна
- Драйвер переключается на `?1002h` (кнопки + колесо): **прокрутка колесом и клики работают**, «чистое движение» больше не приходит. Отключить можно `BOTINOK_MOUSE_MOTION=1`
- Диагностика (py-spy): главный поток в `MouseMove → screen.get_style_at → StylesCache.render → Content.render_strips`, очередь MouseMove копилась

### Изображения в чате: инструмент `image` и ленивый рендер
- Новый инструмент **`image`** (`tools/image_show.py`): принимает картинку файлом или по URL, кладёт её в каталог проекта и возвращает короткий идентификатор. Действия `show`/`list`/`get`/`help`; ошибки — полем `ok:false`
- Чтобы показать картинку, агент вставляет `token` вида `[[image:<id>|подпись]]` в текст ответа — рендер чата сам превращает его в изображение. **В сессии хранятся только идентификаторы**, не файлы
- Каталог: `<session>/project/.botinok/images/<id>.<ext>` + `catalog.json`; без сессии — `~/.botinok/images`. Идентификаторы уникальны и **никогда не повторяются** (`seq` хранится и не сбрасывается, удалённые уходят в `retired`); повторная вставка того же файла переиспользуется по sha256
- Ленивый виджет `ImageBlock` (`core/image_block.py`): картинка всегда во всю ширину чата, пропорции сохранены, высота скроллится. Контейнер фиксированной высоты + вью, смещённый на **видимый срез** строк; разбирается только попавшее на экран
- Рендер (`core/image_render.py`): chafa (секстанты) → встроенный фолбэк + кэши ANSI и готового `rich.Text` с бюджетом памяти. Тяжёлый разбор ANSI вынесен в фоновый поток
- Прокрутка чата подтягивает видимые картинки (`ChatScroll.watch_scroll_y`); в стриминге маркер маскируется (`🖼 [изображение]`); пейджер (F6) рендерит картинки chafa
- Нормализация под терминал: изображение на лету приводится к разрешению текущего окна (`prepare_scaled`, ≈2 px на клетку) и кэшируется, пока размер окна не изменился; JPEG декодируется через `Image.draft`. Рендер идёт **полосами** — chafa рисует только видимый кусок (`render_image_band`), поэтому стоимость не зависит от размера исходника
- Замер (4000×3000): подготовка копии 10 мс, полоса 20 строк 16 мс (кэш 0.04 мс); для 400×300 — 15 мс. Тест `test_image_scaling.py`
- Производительность: на 4К-окне (400×110) с 60 высокими картинками — старт 4/60 рендеров, срез 32/401 строк, **провал UI 68 мс**. Баннер-логотип ограничен `LOGO_MAX_WIDTH=168`/`LOGO_MAX_HEIGHT=48` (раньше maximize окна блокировал UI ~1.5с)
- Тесты: `test_image_render`, `test_image_catalog`, `test_image_in_chat`, `test_lazy_images` (4К), `test_logo_rescale` (реальный maximize 4К)

### Встроенный терминал: inline по умолчанию
- Терминал `shell_exec` теперь открывается **встроенной панелью** (`ShellInline`) над чатом, а не модальным окном: верхнюю часть окна вывода занимает терминал, стрим модели продолжается внизу
- Кнопки панели: **«Развернуть»** — открыть прежнее модальное окно на весь экран, **«Свернуть»** — убрать панель (сессия остаётся живой в панели свёрнутых), **«Закрыть»** — завершить сессию
- В модальном окне появилась кнопка **«В окно»** — вернуть терминал во встроенную панель
- При запуске новой команды панель переиспользуется, а прежняя сессия уходит в панель свёрнутых; одновременно виден не более чем один терминал
- Фокус не отбирается у встроенного терминала во время стриминга, поэтому в него можно печатать
- Панель свёрнутых терминалов обновляется инкрементально (без гонки `remove_children`/`mount`)
- Показ UI из инструмента планируется в контексте UI-цикла (`call_after_refresh`), mount/remove выполняются только из pump
- Панель «Терминалы»: сверху всегда активная строка с тикающим счётчиком секунд от старта; свёрнутые сессии — компактные однострочные строки (время старта + длительность) с кнопкой «✕» для завершения; панель прокручивается
- Заголовок терминала показывает состояние с анимацией: `⠋ имя · идёт Ns`, после выхода — `✔ имя · завершено за Ns (rc=…)`; счётчик обновляется 6.7 раз/с
- В лог терминала по завершении процесса дописывается явный маркер `─── завершено за Ns (rc=…) ───` (или `─── остановлено · Ns ───`), чтобы было видно, что команда закончилась, а не «ещё думает»
- Исправлено подвисание интерфейса при «Развернуть» → «Свернуть» из модального окна: панель основного экрана обновляется только после фактического снятия модалки
- Исправлено, что новый shell не открывался встроенно после закрытия предыдущего: показ UI планируется через `call_next` (на простое `call_after_refresh` не срабатывал), а inline-виджет больше не удаляется из DOM, а скрывается и переиспользуется
- **Критично:** устранено затенение внутреннего атрибута Textual `MessagePump._closed` — виджет терминала выставлял собственный `_closed=True` и Textual вычищал его из DOM, из-за чего переставали работать «Свернуть»/«Развернуть». Свой флаг переименован в `_view_closed`
- Скрытый раньше терминал удерживал фокус на своём поле ввода — фокус возвращается в композер (`_keep_focus`)
- Добавлен `tests/test_shell_pump_clicks.py` — переходы настоящими кликами через `pilot` (именно так ловится конфликт имени)
- Подтверждение опасного действия теперь **встроено в окно вывода** (`#inline_confirm`, `ConfirmInline`) и не накрывает правые панели; модальный `ConfirmationScreen` остался запасным путём. Варианты «Да / Нет / Отменить с причиной» сохранены
- У `OptionList` подтверждения убрана собственная рамка (`border: none`) — вложенная рамка давала артефакты линий поверх панели
- Разворот shell-команд: клик по заголовку терминала показывает команду красиво разбитой на строки (форматтер **shfmt** / `shfmt-py`). Однострочники разворачиваются, `for …; do` сохраняется, тело и `done` выравниваются; при недоступном shfmt показывается исходная команда
- В подтверждении опасного действия команда сразу показана развёрнутой (`shfmt`) в прокручиваемом блоке — видно, что именно агент собирается выполнить; остальные аргументы — pretty-JSON
- В истории сессии тело раскрытого вызова `shell_exec` (клик по строке) показывает команду, развёрнутую `shfmt`, а не сырой JSON

### Веб-кит: единый `web` и надёжные загрузки
- Единый инструмент **`web`** (`action=auto/open/extract/json/download/downloads/search/help`); `web_search`/`open_url`/`web_extract`/`curl` стали legacy-алиасами

- **Мастер настройки (`--wizard`) перенесён на Textual** (`core/textual_prompts.py`): без inquirer/rich.prompt
- **Полностью убраны прямые зависимости от Rich API и inquirer/readchar**: вывод CLI/wizard — plain (`core/cli_io.py`); из `requirements.txt` удалены `rich`, `inquirer`, `readchar` (Rich остаётся транзитивной зависимостью Textual)
- Удалён устаревший `SCROLLBACK_FEATURE.md` (описывал нереализованную фичу Rich-эпохи)
- **Правая колонка переведена на нативные виджеты Textual**: `Performance` (`Static` + `ProgressBar`), шапка (`Static` + CSS-классы), финальный ответ и история — виджет `Markdown`. Панель `Tools Activity` — список карточек-`Collapsible` «время + инструмент + статус», все изначально свёрнуты; по клику карточка раскрывается и показывает детали (запрос, результат, размер). Rich-renderables (`Panel`/`Table`/`Progress`/`Group`/`Markdown`/`DataTable`) из кода убраны; `rich.text` остаётся только для ANSI-рендера (логотип в баннере, лог встроенного терминала) и как транзитивная зависимость Textual.
- **Diagnostic Log перенесён наверх**, в левую колонку, и стал кликабельным `Collapsible`: свёрнутая строка — `Prompt: <последний вопрос>` с обрезкой по ширине (`…`). В раскрытом виде — список всех вопросов сессии карточками: `дата · сколько назад` + обрезанный вопрос, каждая карточка по клику раскрывает полный текст; список прокручивается (`VerticalScroll`, до 14 строк), относительное время обновляется раз в 30 с. Строка `Response (Lines: …)` убрана, нижняя панель `Diagnostic Log` удалена; блок `Performance` не затронут.
- **Многострочный ввод (`Composer` на `TextArea`)** вместо однострочного `Input`: `Enter` — отправить, `Shift+Enter`/`Ctrl+J` — новая строка, `Esc` — очистить, `Alt+↑/↓` — история вопросов. Авто-рост высоты 1→8 строк, дальше внутренний скролл. Вставка из буфера (bracketed paste) вставляет текст целиком и **не** отправляет; на терминалах без bracketed paste действует окно защиты от Enter-ов при вставке. (Заодно исправлена потеря `Input`-ом всего после первой строки при вставке.)
- **Исправлены «сдвиги панелей» на строках с необычными символами**: причина — расхождение ширины ячейки для эмодзи с variation selector (VS16): Rich/Textual считают их за 2, а часть терминалов (glibc, баг locale/32322) — за 1, из-за чего строка «уезжает» и границы соседних панелей смещаются (Textual #5980, Ghostty #8027). Добавлена нормализация ширины (`core/text_width.py`: снятие VS15/VS16/ZWJ, раскрытие табов) в единой точке вставки текста в чат и обрезка по ширине ячейки.

## [0.2] - 2025-03-30

### Новые инструменты
- **vision** — анализ изображений мультимодальной моделью Ollama
  - Автоматическая валидация и конвертация изображений в JPEG
  - Preflight-проверка перед отправкой в Ollama
  - Проверка Content-Type для веб-изображений
- **curl** — загрузка файлов и работа с HTTP-запросами
- **web_extract** — извлечение ресурсов с веб-страниц
- **image_ascii** — ASCII-генератор изображений
- **--update** — инструмент обновления версии botinok

### Новые возможности
- Поддержка macOS
- Режим "только чат" для моделей без поддержки инструментов
- Пользовательские конфиги (в дополнение к проектным)
- Debug-режим для отладки
- Системный промт для управления поведением
- Промты вынесены в отдельную папку `prompts/`, клонируются внутрь сессии
- Опасный режим для file_system инструмента

### Улучшения
- Работа визарда при Ollama через nginx
- Оптимизация работы через SSL с Ollama
- Уменьшение мерцания в SSH-терминалах с низкой скоростью
- Компактный прогрессбар контекста
- При возврате в сессию сразу выводится последний ответ
- Улучшение автообновления с поддержкой Python-зависимостей

### Исправления
- Исправлена ошибка с переменной `ans` в file_system
- Исправлена обработка изображений с неизвестным форматом
- Исправлена валидация изображений: preflight-проверка
- Исправлена обработка ошибок сохранения конфигов

### Прочее
- Расширен скрипт установки для RHEL-систем
- Добавлен логотип в README
- Обновлена документация
